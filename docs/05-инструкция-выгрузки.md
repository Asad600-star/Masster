# Пошаговая инструкция: выгрузка данных из Moodle

Делается один раз. Общее время — около часа, из них 40 минут ждёшь,
пока выполняются запросы.

Конфигурация: **Moodle 3.11.11, MySQL, phpMyAdmin, Linux-сервер.**

---

## Шаг 0. Подготовь соль

Соль — случайная строка, которой шифруются ID студентов. Одна и та же
для всех пяти запросов, иначе файлы не соединятся между собой.

```
Jfur8fuu3wbCnQBXExAX7FnC3ZnoCA45f5ZmBRj9MojDmXjD
```

**Сохрани её прямо сейчас** — в заметки телефона, в отдельный файл,
куда угодно, только не в папку с выгрузкой. Она понадобится, если позже
надо будет догрузить данные и связать их с уже выгруженными.

Никому не передавай, в том числе мне. Пока соль только у тебя,
восстановить по хешу конкретного студента невозможно.

---

## Шаг 1. Подготовь SQL-файл (5 минут)

1. Открой файл `moodle_export_phpmyadmin.sql` в **Блокноте**
   (или Notepad++, VS Code — любой текстовый редактор).

2. Нажми **Ctrl+H** — откроется окно «Заменить».

3. Сделай три замены, каждый раз нажимая **«Заменить все»**:

   | Найти | Заменить на |
   |---|---|
   | `__SALT__` | `Jfur8fuu3wbCnQBXExAX7FnC3ZnoCA45f5ZmBRj9MojDmXjD` |
   | `__DATE_FROM__` | `2024-09-01` |
   | `__DATE_TO__` | `2026-06-30` |

   Период `2024-09-01 … 2026-06-30` — это два последних учебных года.
   Должно хватить на 800–1500 студенто-курсов. Если данных окажется мало,
   расширим назад.

4. **Сохрани файл** (Ctrl+S).

5. Проверь: нажми Ctrl+F, поищи `__` (два подчёркивания). Если что-то
   находится — значит замена сработала не везде, вернись к пункту 3.

---

## Шаг 2. Узнай префикс таблиц (2 минуты)

Обычно он `mdl_`, но бывает свой.

Спроси у администратора значение `$CFG->prefix` из файла `config.php`,
либо посмотри сам в phpMyAdmin: если в списке таблиц слева видишь
`mdl_course`, `mdl_user` — префикс стандартный, ничего менять не надо.

Если таблицы называются иначе (например `mdlx_course`) — сделай ещё одну
автозамену: `mdl_` → твой префикс.

---

## Шаг 3. Зайди в phpMyAdmin

1. Открой phpMyAdmin в браузере (адрес спроси у администратора,
   обычно вида `https://lms.вуз.uz/phpmyadmin`).

2. Войди под своим логином.

3. **Слева в списке баз выбери базу Moodle** — обычно называется
   `moodle`. После выбора справа появится список таблиц.

   ⚠️ Это важно: если базу не выбрать, запросы не найдут таблицы.

---

## Шаг 4. Выполни пять запросов

Для **каждого** из пяти запросов повторяешь один и тот же цикл.

### Цикл (на примере первого запроса)

1. Сверху нажми вкладку **«SQL»**.

2. В большое поле вставь **один запрос** — от слова `SELECT`
   до точки с запятой `;`. Не весь файл целиком, а один запрос.

3. Нажми кнопку **«Вперёд»** (или **«Go»**) внизу справа.

4. Дождись результата. Появится таблица с данными.

5. **Прокрути страницу вниз** — под таблицей найди ссылку
   **«Экспорт»** (или **«Export»**).

6. Откроется страница экспорта:
   - **Формат**: выбери **CSV**
   - Поставь галочку **«Поместить названия столбцов в первой строке»**
     (**«Put columns names in the first row»**)
   - Нажми **«Вперёд»**

7. Файл скачается. **Переименуй его** по таблице ниже.

8. Возвращайся к пункту 1 для следующего запроса.

### Какой запрос как назвать

| Запрос в файле | Имя файла | Что содержит |
|---|---|---|
| ЗАПРОС 1 из 5 | `courses.csv` | Список курсов |
| ЗАПРОС 2 из 5 | `enrolments.csv` | Кто на каком курсе |
| ЗАПРОС 3 из 5 | `weekly_activity.csv` | **Активность по неделям — главный файл** |
| ЗАПРОС 4 из 5 | `grades.csv` | Оценки |
| ЗАПРОС 5 из 5 | `submissions.csv` | Сдача заданий |

## Шаг 5. Если третий запрос отвалится

Запрос 3 самый тяжёлый — он перебирает миллионы строк лога. Возможные
сообщения об ошибке:

- «Maximum execution time exceeded»
- «MySQL server has gone away»
- «Fatal error: Allowed memory size exhausted»
- Просто белый экран или бесконечная загрузка

**Что делать: разбей по годам.** Выполни запрос 3 дважды, меняя даты
прямо в тексте запроса:

**Первый прогон** — вместо `2024-09-01` и `2026-06-30` поставь:
```
2024-09-01   и   2025-06-30
```
Сохрани как `weekly_activity_1.csv`

**Второй прогон** — поставь:
```
2025-09-01   и   2026-06-30
```
Сохрани как `weekly_activity_2.csv`

Оба файла присылай — я их объединю.

Если и так не проходит — режь по семестрам (сентябрь–январь,
февраль–июнь). Хуже от этого не станет.

## Шаг 6. Проверь файлы глазами (5 минут)

**Не пропускай этот шаг.** Открой каждый CSV в Excel и посмотри.

### Что должно быть

Столбец `student_hash` — длинные строки из 64 символов:
```
a3f9c2e1b8d47f6a90c3e5b2d1a8f7c604e9b3d2a1f8c7e6b5d4a3f2e1c9b8d7
```

### Чего быть НЕ должно

- ❌ ФИО, фамилии, имена
- ❌ Адреса электронной почты
- ❌ Телефоны, даты рождения
- ❌ Обычные короткие числа в `student_hash` (например `4521`)

### Если в `student_hash` числа, а не длинные строки

Значит автозамена `__SALT__` не сработала. Вернись к шагу 1, проверь,
что заменил во всех пяти запросах, и выполни заново.

## Отдельно: чего в Moodle нет

Эти два файла **из базы не выгрузить**, их надо просить у людей.
Начни параллельно, не жди окончания выгрузки.

### 1. Формы обучения — в учебную часть

Без этого файла разваливается второй исследовательский вопрос,
а это половина новизны работы. Нужны две колонки:

```
course_id,mode
1234,distance
1235,hybrid
1236,onsite
```

`course_id` возьмёшь из `courses.csv` после первого запроса — можно
прийти в учебную часть уже со списком курсов и попросить проставить
форму обучения напротив каждого.

### 2. Баллы при поступлении — в приёмную комиссию или деканат

```
student_hash,entry_score,year_of_study,program
```

⚠️ Хешировать **той же самой солью**. Если они не смогут — попроси
администратора Moodle сделать выгрузку с хешированием, как в остальных
запросах.

Это контрольная переменная. Без неё рецензент спросит, не меряет ли
модель просто исходную подготовку студента.
