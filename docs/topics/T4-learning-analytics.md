# Тема 4 — план исследования

## Рабочее название

> **Predicting Student Outcomes from Learning Management System Behavioural
> Data in Hybrid Higher Education: Evidence from a Central Asian University**

Варианты для подгонки под конкретный журнал:

- «Early identification of at-risk students using LMS engagement indicators:
  a multi-course study in a hybrid learning context»
- «Which LMS behaviours actually predict academic performance? A comparison
  of engagement metrics across distance and traditional course formats»

Заголовок содержит четыре обязательных элемента: предмет (LMS behavioural
data), результат (student outcomes), контекст (hybrid higher education),
географию (Central Asian university). Последнее — сознательно, это несущий
элемент новизны.

## Научный пробел

Систематический обзор Segura-Altamirano et al. (2026), источник [44],
охватил 21 эмпирическую работу за 2020–2025 и зафиксировал:

1. подавляющее большинство исследований выполнено в западном и
   восточноазиатском контексте;
2. большинство работ анализируют один курс или одну дисциплину;
3. сопоставления предсказательной силы разных метрик вовлечённости
   между дистанционным и очным форматами почти нет.

Отчёт LeapSpace независимо фиксирует то же самое: системы оптимизированы
под административные функции, педагогический потенциал недоиспользован
(источники [4], [58]).

**Формулировка пробела для Introduction:** предсказательные модели
успеваемости на данных LMS валидированы преимущественно в ресурсно
обеспеченных западных вузах; переносимость этих моделей на институты с
иной инфраструктурой, иной культурой преподавания и иными паттернами
использования LMS остаётся непроверенной.

## Исследовательские вопросы

**RQ1.** Какие поведенческие индикаторы LMS (частота входов, регулярность,
объём просмотренных материалов, своевременность сдачи, участие в форумах)
наиболее сильно связаны с итоговой успеваемостью?

**RQ2.** Различается ли предсказательная сила этих индикаторов между
дистанционными, гибридными и очными курсами?

**RQ3.** На какой неделе семестра модель достигает точности, достаточной
для практического вмешательства?

RQ3 — самый ценный. Он превращает работу из описательной в практически
применимую, а рецензенты в этой области прямо спрашивают «and what do you
do with this?».

## Гипотезы

| | Формулировка |
|---|---|
| H1 | Регулярность взаимодействия с LMS (равномерность распределения активности по неделям) предсказывает успеваемость сильнее, чем суммарный объём активности |
| H2 | Предсказательная сила поведенческих индикаторов выше в дистанционных курсах, чем в очных, где значимая часть учебного взаимодействия происходит вне системы |
| H3 | Своевременность сдачи первых заданий — самый ранний надёжный предиктор итогового результата |

H1 сформулирована так намеренно: она контринтуитивна и потому интереснее.
Если подтвердится — это самостоятельный вклад; если нет — тоже
публикуемый результат.

## Данные

### Что выгружать

**Из LMS (Moodle: таблицы `logstore_standard_log`, `course_modules_completion`,
`grade_grades`):**

| Поле | Назначение |
|---|---|
| Псевдонимизированный ID студента | Ключ связи |
| ID курса, формат курса (дист./гибрид./очный) | Группирующая переменная |
| Метки времени всех событий | Регулярность, динамика по неделям |
| Тип события (просмотр, отправка, форум, скачивание) | Индикаторы вовлечённости |
| Дедлайны и фактическое время сдачи | Своевременность |
| Оценки за задания и итоговая | Зависимая переменная |

**Из учебной части:**

- курс/год обучения, направление подготовки;
- форма обучения;
- при возможности — балл при поступлении (контроль исходной подготовки).

Балл при поступлении важен: без него рецензент спросит, не меряет ли
модель просто исходную мотивацию студента.

### Целевой объём

Минимум **20 курсов × 2 семестра**, ориентир 800–1500 студенто-курсов.
При меньшем объёме анализ по подгруппам (RQ2) потеряет мощность.

### Обезличивание — обязательно до анализа

1. Заменить ФИО и студенческие ID на суррогатные (хеш с солью, соль
   хранится отдельно от датасета и **не** попадает в репозиторий).
2. Удалить e-mail, телефоны, точные даты рождения, тексты сообщений форума.
3. Даты событий сдвинуть в относительную шкалу «неделя от начала курса».
4. Курсы с малым числом студентов (< 10) либо объединить, либо исключить —
   иначе возможна реидентификация.

Сырые выгрузки кладутся в `data/raw/` — этот каталог в `.gitignore` и
никогда не попадает в репозиторий.

### Разрешения

До выгрузки нужно получить и **сохранить письменно**:

- разрешение администратора LMS на выгрузку;
- одобрение этического комитета вуза (или письменное подтверждение, что
  для обезличенных ретроспективных данных оно не требуется);
- согласование с юридическим отделом на предмет закона о персональных данных.

Раздел «Ethics statement» с номером одобрения — обязательное требование
почти всех целевых журналов. Без него статью развернут на этапе submission.

## Методология

**Дизайн:** ретроспективное обсервационное исследование на данных
нескольких курсов.

**Пайплайн:**

1. Feature engineering — из сырых логов собрать индикаторы:
   - `total_events`, `active_days`, `sessions_per_week`
   - `regularity` — энтропия Шеннона распределения активности по неделям
   - `submission_lead_time` — среднее опережение дедлайна в часах
   - `forum_posts`, `forum_reads`, `resource_views`
   - `first_week_activity`, `first_assignment_ontime` (для RQ3)
2. Описательная статистика и корреляционный анализ.
3. Иерархическая линейная регрессия (студенты вложены в курсы —
   многоуровневая модель обязательна, иначе рецензент справедливо
   укажет на нарушение независимости наблюдений).
4. Сравнение групп по формату обучения → RQ2.
5. Классификация «в зоне риска / нет» с накоплением данных по неделям,
   метрики AUC-ROC / precision / recall по неделям → RQ3.
6. Проверка устойчивости: кросс-валидация с разбиением **по курсам**,
   а не по студентам.

**Инструменты:** Python (pandas, scikit-learn, statsmodels) либо R (lme4).
Скрипты — в `analysis/`.

## Структура статьи

| Раздел | Объём | Источник содержания |
|---|---|---|
| Abstract | 250 слов | пишется последним |
| 1. Introduction | 800 | каркас из отчёта + формулировка пробела |
| 2. Literature Review | 1500 | источники T4 из `references.bib` (22 записи), **переписанные своими словами** |
| 3. Methodology | 1200 | полностью своё: контекст, выборка, переменные, этика, анализ |
| 4. Results | 1500 | полностью своё: таблицы, графики |
| 5. Discussion | 1200 | сопоставление с [44], [66], [67], [14] |
| 6. Limitations & Conclusion | 600 | один вуз, ретроспективность, вне-LMS активность не учтена |

Итого ~7000 слов — типичный формат для целевых журналов.

Из отчёта LeapSpace берётся **структура** разделов 1–2 и **ссылки**.
Текст — не берётся.
